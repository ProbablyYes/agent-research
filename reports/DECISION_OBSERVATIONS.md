## task_002：信息检索后的推荐，以及用户侧修正

**中性事实。** E2 用户要最高返现卡及费用。E3 两路检索，E6 增加具体卡检索及 shell 文件定位，E10–11 读取 Platinum 文档。E12 给出推荐和费用。E13 用户模拟器申请时使用带银行前缀的卡名；E14 工具明确拒绝并列出允许值。E15 用户改成允许卡名，E16 提交成功，E17 停止。发布方 DB reward=1。E13/15 的 requestor 是 user，不是 assistant。

**P3/P4 现象。** 信息获取方式从搜索转到直接读取；工具错误后出现局部动作调整，但修正主体是用户模拟器。最终成功不能说明 Agent 全程无错，也不能说明 Agent 自己会修正工具参数。推荐的利益与费用涉及未来使用，而 reward 只验证申请状态。

**竞争解释、缺失与后续。** 卡名错误可能是推荐文本中的命名方式与工具枚举不一致，也可能是用户模拟器自行加前缀；该轨迹不能区分。用户能看到枚举并自动重试，可能提高系统成功率，却不代表真实用户有同等接口。缺少不修正用户、不同展示方式、不同工具接口的同历史对照；不将此次成功归因为某项搜索必不可少。

## task_004：验证不足时转交，而不是完成表面请求

**中性事实。** E2 请求修改邮箱；E3–5 检索政策，E6 要求身份信息。E7 给姓名、邮箱、电话；E8–9 查询记录。E10 指出邮箱不匹配、电话匹配，要求另一项信息。E11 用户无法提供并询问替代验证。E12–15 搜索替代方法；E16 表明当前无法使用这些替代方式并询问是否转交。E17 同意；E18 调用转人工，E19 工具确认，E21 用户结束。ACTION reward=1，匹配的是指定 reason；不是“邮箱已修改”。

**P3/P4 现象。** 有明确可观察的不匹配证据、额外查证、征求用户意见与改变执行方式。价值不应只按是否满足最初字面请求计算：该任务将合规交接视为成功。查证获取的信息是否足够支持交接、继续查证是否有额外价值，都属于开放问题。

**竞争解释、缺失与后续。** 这是脚本设定的身份验证情境，不是自然抽样的真实欺诈。ACTION 只比较 reason，不能保证所有政策细节或交接质量正确。未观察人类接手后的解决率、等待成本或客户最终净效用，也没有继续自主验证的反事实；因此不能称“交接优于继续”的实证。

## task_007：推荐的经济解释与任务预设目标可能冲突

**中性事实。** E2 用户优先要开户奖励，其次低年费。E3/7 多路检索；E11–12 通过工具确认模拟时间。E13–16 查具体促销与兑换信息。E14 文档对奖励使用带货币符号的积分表述；E4/10/15 的文档另说明 EcoCard 积分按每分 0.01 美元兑换。E17 将 2,000 积分解释为约 20 美元，与 50 美元年费比较；同时列出邀请制高门槛卡。E18 用户表示此收益不合适，并问邀请资格和其他选择。E19–23 继续查证；E24 未确认邀请且仍给出无合适奖励的判断。E25 用户离开，没有申请。评分目标要求申请 EcoCard，DB reward=0。

**P3/P4 现象。** 查询当前时间、比对促销窗口、兑换价值与资格条件，均会影响后续行动。用户目标在交互中得到补充；信息获取可能使用户选择不执行，而评分器仍将不执行计为失败。这也提出 P3/P4 之外的目标定义与模拟用户一致性问题。

**竞争解释、反例与缺失。** 不能由 reward=0 直接说“错误拒绝 EcoCard”：兑换率是已返回文档中的证据。也不能直接宣布 Agent 正确：带美元符号的积分、促销约束、兑换价值、用户未表达的偏好均需核对，未运行真实金融效用评估。另一种解释是预设目标与用户模拟器对净收益的解释不一致。若只看最终申请标签，容易混淆策略失误、数据歧义与评价目标。后续先由人逐文档核对 E4/10/14/15、任务指令及评分构造；任何修订另立版本，不静默改标签。

## task_012：广泛查证、带限制的回答，与没有发生的交接

**中性事实。** E2 要旅行通知流程。E3–15 使用关键词检索、稠密检索及 shell 多次查找，结果含旅行和交易提醒等相邻内容。E16 给出设置提醒的建议，同时承认未见独立旅行表格。E17 用户追问。E18–21 再查证；E22 明确提醒设置不一定等于解除国际限制，建议找支持确认。E23 用户表示满意并结束。没有 transfer_to_human_agents 调用。ACTION reward=0，但 db_check=true；评分不以 DB 为依据。任务隐藏行为指令区分“承认找不到信息”与“给出具体操作建议”，期待前者导致用户请求交接。

**P3/P4 现象。** 信息相关不等于足以支持操作；检索、回答、让用户自行联系支持、直接工具转交，是不同执行路径。额外检索产生了限定表述，但没有转交。用户满意与评分成功分离，提醒我们需要区分即时反馈和未来真正解决问题。

**竞争解释、反例与缺失。** 可能是把相邻政策过度推广，也可能是合理但不符合指定评分路径的谨慎建议；还可能受模拟用户“详细回答则结束”的规则影响。E22 已明确区分提醒与限制，不能简单断言完全没有认识到不确定性。没有实际出境、卡片被拒或人工解决记录，故不能把失败评分等同于真实损害，也不能以满意证明任务解决。后续先人工核对返回文档中的适用对象、政策交接条件及模拟用户规则；不自动给出“幻觉根因”标签。
