# Phase 2：P3/P4 覆盖与补充来源审查

## 判断

**τ-Knowledge 足以支持第一轮问题发现、证据定位和人工审阅，但不足以单独支持 P4 长期价值估计，更不足以证明 P3 的执行改变提高净效用。** 这不是修改 Phase 1 结论，而是基于新增冻结样本对适用范围的专项审查。P1/P2/P5 与其他新问题独立保留，不把项目收窄成恢复窗口或工具错误检测。

本批 50 条有 21–120 条消息，中位数 58.5；发布 duration 约 48–954 秒。消息包含工具返回和用户发言，不是同数量的 Agent 决策步；耗时字段也不等同于实际业务效果经历的时间。22 条含用户工具调用。没有现实客户的后续数周结果。

## 推荐的一个补充：SWE-smith 仓库修复任务及官方轨迹

来源：[官方轨迹数据集](https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories)、[官方资产说明](https://swesmith.com/getting_started/assets/)、[SWE-smith 论文](https://arxiv.org/abs/2504.21798)。官方说明其生成软件任务并公开 SWE-agent 轨迹。这里不依赖“有下载按钮”推断可用性，已实际请求一条公开记录并解析完整已发布消息。

实际取得的补充样本：

- task instance：`django-money__django-money.835c1ab8.func_pm_ctrl_shuffle__viqnyl9u`。
- 模型：`claude-3-7-sonnet-20250219`；traj_id 见 SUPPLEMENT_MANIFEST；`resolved=true` 为发布标签，未重跑评分。
- HTTP 200，75,628 字节；viewer `truncated_cells=[]`；49 条完整已发布消息，24 次 assistant 行动、23 个工具返回，末尾是 submit，没有附随最终返回。
- 请求响应 SHA256：`3a9355f21a9d58b7bbd9dceb5c58d6e0d9423d9d9ded3bce7c170e42524f5f15`。
- 数据集声明 MIT；保存原始响应、字段、任务描述、模型 ID、哈希与完整可读版。[补充可读轨迹](../public_trajectory_research/phase2/supplement/SWESMITH_READABLE.md)。

**已观察的依赖结构：** E3–21 读取 widgets/model/form 相关代码；E23 创建复现脚本，E25–26 执行并出现验证失败；E27–28 修改 widget 条件顺序；E29–30 重跑显示验证通过；E31–44 增加边界情况并再次检查；E45 提交后，E46 返回清理/复核要求；E47–48 删除复现脚本，E49 再提交。准备产物、代码修改、重复可执行检查和最终交付要求形成跨步依赖，较单纯检索问答更适合补充 P4。

**竞争解释与限制：** 这是官方处理后的消息历史，非 provider 原始运输日志；保留了从初始任务至最终提交的全部发布消息，但不能证明所有内部状态齐全。实例是生成的缺陷而非已核实自然真实 Issue；模型比当前 frontier 老。`patch` 字段为空，代码编辑仍在消息中，未独立重建最终 diff；没有该行的时间与 token 成本。数据卡正文仍提 5,017 条训练轨迹，tool split 元数据为 24,100，不能照正文估算实际分母，也不能假设各格式 split 是独立运行。当前只验证一个样本，不声称整库质量合格或适合小时级任务。

HF viewer URL 可变，修订核对和哈希能固定本地证据，但不能把该 URL 冒充不可变 provider 原始文件。后续若扩样，应先核对固定修订文件与任务元数据；本轮不扩样。

## 为什么没有直接推荐较新的 Terminal-Bench 镜像

本轮实际检查发现：

1. 官方旧 `/leaderboard/terminal-bench/2.0` 路径重定向到新首页，旧抓取脚本路径不再能按原方式核验。
2. `yoonholee/terminalbench-trajectories` 第 0 行 `steps=null`；第 10000 行虽含 23 步，但 system message 是未解析 `$31` 引用。
3. `Jiacheng-Zhu-AIML/terminal_bench_trajectories` v0.1 release 可下载，19,369,540 字节。选取 train-fasttext / Terminus-2 / Opus 4.6 的一个 ATIF 记录有 61 步，但任务说明 `$31` 和工具反馈 `$6c` 等仍未解析。未将它作为“完整原始轨迹”验收。

这些是所检查路径/文件的问题，不是断言 Terminal-Bench 所有日志都缺失。拒收记录和原字节保存在 supplement，未混入主样本或精读清单。没有以更强模型的名义掩盖证据不完整，也没有用摘要替代实际轨迹核验。
