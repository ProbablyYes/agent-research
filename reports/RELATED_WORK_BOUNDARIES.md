# 相关工作边界 — 2026-10-20

P3/P4 保持开放；P1/P2/P5 及新猜想独立保留。本轮只有公开记录提取及待人工核验的描述，不提出算法、不建立强制分类体系、不自动判定真实根因。

| 已有工作 | 已研究的内容 | 本轮不应重复声称 | 仍可能需要后续实验回答 |
|---|---|---|---|
| [Failure as a Process](https://arxiv.org/html/2607.09510v1) | 错误发生/锁定/可观察时刻、恢复、触发因素、跨模型与 scaffold、前缀监测 | “首次发现错误会积累”“首次研究恢复窗口/失败后持续行动” | 在可执行替代方案下，改变执行的净效用；事后锁定是否真对应干预无效；检测与控制价值如何区别 |
| [τ²-bench](https://arxiv.org/html/2506.07982v1) | 双方控制共享环境、协作与多次运行可靠性 | 把用户行为全部当 Agent 动作，或把模拟用户当真人 | 用户适应如何改变行动价值；用户侧修正是否掩盖 Agent 问题 |
| [τ-Knowledge](https://arxiv.org/html/2603.04370v1) | 检索与工具使用耦合，跨文档约束，检索策略/效率，提供关键文档的对照，以及用户模拟可靠性 | “发现检索不等于正确利用信息”“首次发现搜索有成本” | 在同一历史下多搜、澄清、执行、交接等选择的长期净价值，及何种可观察证据支持选择 |
| [SWE-Marathon](https://www.swe-marathon.org/swe-marathon-paper.pdf) | 超长程软件任务、执行进展、提前结束、验证器与评测规避 | 将工具步数增加当作独有长程贡献 | 可访问完整日志之后，评测器与真实质量的偏差是否改变控制决策；目前未取得原始日志 |

区分三个对象：发布方 reward、用户模拟器表达的满意、研究者关心的长期净效用。三者可能不同；本批不能将任意一个直接当作真实价值的全部。

本轮四条中没有随机干预、同状态配对、独立客户效用或替代执行结局。观察到搜索、转人工、修正、放弃，不等于已估计这些行为的因果价值。也不应从 reward=0 倒推某一步一定是根因。

对既有标注保持距离：Failure 的标签包含事后全轨迹知识，不能直接作为部署特征。公开 CODEBOOK 的长轨迹抽读和人工复核边界尚有待核验；不把其 taxonomy 强套到本批客服任务。

后续问题只作为候选，不在本轮执行：在相同信息历史下比较继续查证、向用户澄清、直接执行、交接与停止；完整记录行动和信息获取成本、客户目标与评分器差异。是否采用任何干预或状态表示，应由人工精读和后续研究设计决定。现阶段不能声称新的 P3/P4 算法或总体统计结论。
